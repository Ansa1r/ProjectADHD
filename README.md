# ProjectAHDH

Рабочее название Android-приложения для самоконтроля, привычек и управления отвлечениями.

Главная цель проекта — создать приложение, которое отслеживает использование выбранных пользователем приложений, анализирует время в них и в нужный момент напоминает о поставленных целях и привычках.

На раннем этапе проект разрабатывается без маскота и сложного дизайна. Сначала реализуется ядро приложения: хранение данных, отслеживание приложений, логика лимитов, напоминания и отладка.

## Технологии

- Kotlin
- Jetpack Compose
- Android Studio
- Gradle Kotlin DSL
- Room
- DataStore
- Android UsageStatsManager
- ViewModel
- Kotlin Coroutines / Flow

В дальнейшем могут быть добавлены:

- overlay-интерфейс поверх других приложений;
- маскот и система его развития;
- расширенная статистика;
- голосовой дневник;
- AI-функции;
- синхронизация между устройствами;
- серверная часть.

## Первая версия

Первая техническая версия должна уметь:

- создавать, редактировать и удалять привычки;
- отмечать привычки выполненными;
- выбирать приложения для отслеживания;
- запрашивать необходимые разрешения Android;
- получать статистику использования приложений;
- определять превышение установленного лимита;
- создавать напоминания;
- хранить историю событий;
- показывать диагностическую информацию в Debug Screen.

Первая версия намеренно не включает:

- маскота;
- анимации;
- AI;
- авторизацию;
- сервер;
- подписки;
- медитации;
- голосовой дневник.

## Архитектура

Основные части проекта:

- `ui` — экраны, состояние интерфейса и ViewModel;
- `domain` — бизнес-логика;
- `data` — база данных, настройки и репозитории;
- `monitoring` — работа с Android API для отслеживания использования приложений.

Логику принятия решений желательно держать максимально независимой от Android API, чтобы её можно было покрывать обычными unit-тестами.

```text
UsageStatsManager
        ↓
UsageMonitor
        ↓
InterventionEngine
        ↓
UseCase
        ↓
UI / Notification
```

## Запуск

1. Установить Android Studio.
2. Открыть корневую папку проекта.
3. Дождаться Gradle Sync.
4. Запустить Android Emulator или подключить физический Android-смартфон.
5. Запустить конфигурацию `app`.

Для функций, связанных с `UsageStatsManager`, фоновыми ограничениями и overlay, рекомендуется дополнительно тестировать приложение на реальном устройстве.

## Git

Рекомендуемая схема веток:

- `main` — стабильное состояние проекта;
- `develop` — текущая разработка;
- `feature/<name>` — отдельные крупные функции;
- `fix/<name>` — исправления.

Примеры:

```text
feature/habits
feature/app-monitoring
feature/debug-screen
fix/usage-permission
```

Не следует добавлять в репозиторий:

- `local.properties`;
- каталоги `build`;
- `.idea`;
- APK/AAB;
- ключи подписи;
- `.env` и файлы с секретами.

## Тестирование

- unit-тесты для бизнес-логики;
- UI / instrumentation-тесты на Android Emulator;
- ручное тестирование на реальных устройствах.

Особое внимание:

- работа в фоне;
- сохранение состояния;
- разрешения Android;
- разные версии Android;
- особенности оболочек Samsung, Xiaomi, Honor и других производителей.

## Статус

Проект находится на стадии первоначальной разработки.

Сначала создаётся функциональное ядро приложения. Визуальная часть, маскот, анимации и дополнительные функции будут добавляться после стабилизации основной логики.
