# ProjectADHD 0.2 Pre-alpha

**Stage 2 UI/UX Revision.** Локальное обновление существующего Stage 2 на Kotlin, Jetpack Compose, Room, DataStore и MVVM. Package/namespace: `com.ansa1r.projectadhd`. Version: `0.2.2-pre-alpha`, code `4`. Основа — GitHub commit `d18fa8bdf499199ff8902b025cbea7b11d29ba06` от 2026-10-01; все 137 файлов сверены с Git blob SHA до правок.

Приложение отслеживает непрерывную сессию в выбранных приложениях. При достижении лимита:

| Задачи сегодня | Действие |
| --- | --- |
| Есть незавершённые активные привычки | BLOCK: окно с маскотом перекрывает приложение и перехватывает касания |
| Есть активные привычки, все выполнены | PRAISE: короткая похвала, без блокировки |
| Активных привычек нет | NONE: блокировки нет |

Задачи Stage 2 — существующие активные Habit. Отдельной системы Task нет. Добавление, редактирование, архивирование, отметки выполнения, выбор приложений, лимиты, статистика и история Stage 1 сохранены.

## Блокировка и разблокировка

В Room сохраняется одна текущая/последняя BlockSession на пакет приложения. Уход на Home скрывает окно, но сохраняет блокировку. Возвращение в заблокированное приложение снова вызывает окно после получения события Android. Одновременно отображается не более одного окна.

Кнопка **«Посмотреть дела»** открывает существующую MainActivity прямо на экране привычек. Она сама не снимает блокировку. Нужно выполнить привычку, которая была незавершённой на момент начала блокировки. Сохраняются ID таких привычек и время отметки; ранее выполненные привычки, включая снятие и повторную установку старой отметки, не засчитываются.

После нового выполнения BlockSession закрывается и приложение получает полный новый интервал. Отметка и release записываются одной транзакцией. Если одна задача подходит к нескольким активным блокировкам, она освобождает все эти приложения. При смене дня, удалении/деактивации всех доступных для разблокировки задач или отключении отслеживания устаревшая блокировка отменяется с отдельной причиной в истории.

В **Настройках → Остановить мониторинг** есть аварийный выход: убрать окно, остановить сервис, снять активные блокировки. Такая же команда есть в постоянном уведомлении и Debug. Обычной кнопки обхода на блокирующем окне нет.

## Маскот и Praise

`MascotView` централизует три состояния: IDLE → исходный `06_mascot_idle.png`, BLOCKING → исходный `05_mascot_blocking.png`, PRAISE → отдельный радостный маскот на основе `03_mascot_happy_reference.png` с удалённым фоном. `04` рассмотрен как альтернативный референс. Исходные idle/blocking/background сохранены побайтово; happy asset имеет настоящий alpha-канал без белого/градиентного прямоугольника. Все используемые PNG включены в `drawable-nodpi`.

Основной фон `07_background_main.png` подключён на Home, Habits, Apps, Statistics, Profile, Debug и PRAISE. Settings и все его подразделы используют однотонный графитовый фон. BLOCK показывает реальное приложение через фиолетовый scrim; непрозрачного фонового изображения и рамки телефона в нём нет. Палитра карточек и кнопок сохранена в `Color.kt`/`Theme.kt`.

Нижняя панель содержит ровно пять иконок: Главная, Привычки, Приложения, Статистика, Профиль. Подписей нет; accessibility-описания и индикатор выбранной вкладки сохранены. Профиль — отдельная локальная заглушка. Шестерёнка справа сверху Главной открывает компактное меню Settings: Разрешения, Экран блокировки, Тема интерфейса, Конфиденциальность, Для разработчика. Последний пункт и Debug доступны только в debug build. Тема и конфиденциальность открывают самостоятельные экраны-заглушки. На Главной остаётся лишь краткое предупреждение о недостающих разрешениях со ссылкой; выдача разрешений находится в Settings.

В **Настройки → Экран блокировки** ползунок задаёт прозрачность затемнения: 30–90%, шаг 5%, по умолчанию 65%. Preview меняется сразу; каждое значение сохраняется в Preferences DataStore (`blocking_overlay_opacity_percent`). Flow передаёт его существующему OverlayController без перезапуска Activity/сервиса/мониторинга. Только scrim получает alpha; окно, маскот, текст и кнопка сохраняют alpha=1. Касания перехватываются. Здесь же сохранены прежние интервалы Praise и резервных уведомлений.

В списке приложений отображаются реальные иконки из PackageManager, имя, пакет, выбор и лимит сессии. `AppIconLoader` загружает иконки на IO, ограничивает размер bitmap и LRU-кэш 4 MiB; удалённые/недоступные приложения получают запасной значок. В Room Drawable/Bitmap не хранятся. После обновления списка обновляются и иконки.

Launcher использует только happy-референс **08_app_icon_reference.png**: прозрачный счастливый маскот на зелёно-голубом градиенте. Foreground с отступами помещён в безопасную зону adaptive icon; есть legacy и round варианты. Исходник 08 сохранён в `docs/assets/`. Подробности обработки — [ASSETS.md](docs/ASSETS.md).

При первом обычном запуске Activity в процессе `StartupHost` показывает того же маскота на полноэкранном зелёно-голубом градиенте, поворачивает его 0°→90°, заменяет названием ProjectADHD и доворачивает -90°→0°. После короткой паузы — fade к Home. Compose-последовательность занимает 1840 мс. Системный SplashScreen стилизован тем же маскотом/зелёным цветом и убирается без дополнительной задержки удержания. «Посмотреть дела», восстановление Activity и повторное открытие в живом процессе пропускают собственную заставку; фон 07 в ней не используется.

Praise — небольшое окно на 4 секунды с `FLAG_NOT_TOUCHABLE`; на Android 12+ его opacity ограничена системным порогом пропуска касаний. По умолчанию между похвалами 30 минут; настройка сохраняется отдельно от паузы резервных уведомлений. BlockSession для Praise не создаётся.

## Запуск

1. Распакуйте ZIP в отдельную папку. В корне находятся `app/`, `gradle/`, `docs/` и Gradle-файлы. Откройте именно эту папку в Android Studio.
2. Используйте рабочую среду текущего Stage 2. Версии AGP, Gradle, Kotlin, compileSdk и существующих библиотек не менялись: AGP 9.4.1, Gradle 9.6.0, Kotlin 2.2.10, compile/target SDK 37, min SDK 24. Добавлена `androidx.core:core-splashscreen:1.2.0`. Нужны установленный Android SDK и подходящий JDK Android Studio; зависимости загружаются при первой сборке.
3. Дождитесь Gradle Sync. При необходимости создайте локальный `local.properties` через Android Studio. В архив его не включали.
4. Выполните `./gradlew testDebugUnitTest assembleDebug`. Windows: `gradlew.bat testDebugUnitTest assembleDebug`.
5. Установите `app/build/outputs/apk/debug/app-debug.apk` на эмулятор/устройство. Для проверки миграции установите поверх Stage 1 тем же signing key, без удаления данных.
6. Откройте **Главная → шестерёнка → Разрешения**. Выдайте Usage Access, уведомления и включите оба канала уведомлений. Для реального overlay дополнительно разрешите «Отображение поверх других приложений».
7. Создайте две активные привычки, выберите Chrome или другое тестовое приложение и лимит 1 минута. Запустите мониторинг вручную.

Android 8+ поддерживает используемый `TYPE_APPLICATION_OVERLAY`. На Android 7 (API 24–25) сохранён режим уведомлений. Без overlay permission мониторинг также работает через уведомления, а недоступность окна видна в Debug. На некоторых версиях Android экран специального разрешения открывает общий список приложений — выберите ProjectADHD.

## Ограничения Android и приватность

ProjectADHD перекрывает выбранное приложение overlay-окном, а не создаёт абсолютную системную блокировку. Системная навигация остаётся доступной. Собственная Activity, распознанные Settings, launcher и System UI исключены. Мониторинг опрашивает события примерно раз в секунду; переключения зависят также от задержки UsageEvents. Над ProjectADHD окно удаляется непосредственно при `onStart`.

Android/OEM может задерживать события, завершать сервис, скрывать чужие окна или запрещать запуск Activity. Приложение не пытается обходить эти ограничения. Окна ниже системных панелей, аппаратный ввод и системные поверхности не превращаются в kiosk. Мультиоконность, PiP и несколько дисплеев требуют отдельной проверки; штатный сценарий Stage 2 — одно приложение на основном экране. Другие приложения могут отклонять касания при любом перекрытии.

После остановки процесса/перезагрузки мониторинг нужно включить вручную. Активные блокировки хранятся до выполнения задачи, отмены или явного STOP и восстанавливаются при новом запуске мониторинга. Уведомления зависят от системных каналов и «Не беспокоить». `specialUse` FGS не означает автоматическое одобрение публикации в Google Play.

Нет INTERNET permission, сервера, аналитики, аккаунтов, AccessibilityService, root или device owner. Данные локальны, резервное копирование отключено. Лицензия сохранена из Stage 1; иконки запуска обновлены. Исходный GitHub-репозиторий не изменялся.
