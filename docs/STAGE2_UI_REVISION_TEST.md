# Stage 2 UI Revision — ручная приёмка

> Исторический документ UI Revision. Актуальные правила Apps, Profile и показа startup при каждом возврате из фона описаны в STAGE2_APP_SELECTION_PROFILE_REPORT.md и STAGE2_APP_SELECTION_PROFILE_TEST.md.

Это **план**, не отметка об успешном прохождении. В среде подготовки отсутствуют Android SDK и эмулятор; Gradle не скачался из-за `Network is unreachable`. Запишите модель/API/OEM, размер и ориентацию экрана, масштаб шрифта, режим системной навигации, результат и скриншоты/видео каждого раздела.

## Подготовка

Распакуйте полный ZIP в отдельную папку, откройте корень в Android Studio и дождитесь Sync. Используйте рабочие JDK/SDK текущего Stage 2. Package остаётся `com.ansa1r.projectadhd`, versionName — `0.2.2-pre-alpha`, versionCode — 4.

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebug
./gradlew connectedDebugAndroidTest
```

На Windows используйте `gradlew.bat`. Ожидаемые suites по исходникам: 72 unit-теста и 13 Android-тестов. Последняя команда требует устройства. Сохраните фактический вывод: наличие тестов не доказывает их прохождение. Установите `app/build/outputs/apk/debug/app-debug.apk`; для проверки сохранения данных — поверх предыдущего Stage 2 с тем же signing key, без удаления данных. На отдельной чистой установке проверьте default opacity.

Выдайте разрешения через **Главная → шестерёнка → Разрешения**. Создайте две активные незавершённые привычки, выберите тестовое приложение с лимитом 1 минута и вручную включите мониторинг на Главной. Проверьте хотя бы API 26/31/33+ и доступную современную версию Android. API 24–25 проверяется отдельно как notification fallback.

## A. Launcher icon

- Счастливый персонаж с закрытыми глазами и зелёным шарфом соответствует 08; фон зелёно-голубой. Нет idle/blocking или стандартного Android значка.
- Проверьте circle, squircle, rounded square и другие доступные маски: весь персонаж и капли помещаются, нет обрезания или фонового прямоугольника.
- Проверьте round icon, themed/monochrome icon и legacy API 24–25.
- Если launcher кеширует значок, обновите launcher; не удаляйте данные приложения ради проверки миграции.

## B. Navigation

- Ровно пять нижних иконок: Главная / Привычки / Приложения / Статистика / Профиль. Визуальных подписей нет, активный пункт выделен.
- С TalkBack каждая иконка имеет понятное название; выбранное состояние озвучивается.
- Откройте все пять вкладок, выполните возврат Back, поворот экрана и повторное открытие. Профиль показывает локальную заглушку; регистрация и сеть отсутствуют.
- Внизу нет Settings. На Главной справа сверху шестерёнка, ведущая в Settings; кнопки Debug там нет.
- Home содержит только краткую ссылку-предупреждение о разрешениях при необходимости, без набора permission-кнопок.
- Фон 07 присутствует на пяти вкладках и Debug; purple-карточки сохранены. В Apps видны настоящие иконки, display name и package; само приложение нельзя выбрать для блокировки.

## C. Settings

- Корень — компактное меню на однотонном тёмном фоне. Каждая карточка открывает отдельный экран, Back возвращает в меню.
- «Разрешения»: Usage Access, Overlay, уведомления и каналы; объяснения, корректные статусы, рабочие системные переходы. После выдачи/отзыва и возвращения статус обновляется.
- «Экран блокировки»: ползунок, значение, preview и сохранённые настройки пауз Praise/fallback. Default 65%; диапазон 30–90%; все 13 допустимых положений с шагом 5%.
- «Тема интерфейса» и «Конфиденциальность»: реально открывающиеся заглушки.
- В debug build «Для разработчика» → «Отладка» открывает прежние инструменты и диагностику opacity. В release build нет пункта Developer и Debug destination.
- Settings и все его подразделы не используют фон 07. Debug использует его. В меню Settings сохранён работающий аварийный STOP.

## D. Startup animation

1. Остановите процесс, затем откройте приложение через launcher. Запишите экран.
2. Первый системный кадр стилизован happy-маскотом, не Android Studio icon. Переход на полный зелёно-голубой градиент выглядит естественно, без второй отдельной заставки/вспышки.
3. Маскот по центру → плавный flip 0°→90° → название ProjectADHD -90°→0° → короткая пауза → fade к Home. Нет резкой подмены контента. Фон 07 появляется только в Home.
4. Измерьте собственную анимацию: номинально 1840 мс, целевой диапазон около 1.7–2.2 с. Отдельно запишите время системного холодного старта: оно зависит от ОС/устройства и не входит в фиксированные Compose-задержки.
5. Повторно откройте приложение в живом процессе и поверните экран: анимация не повторяется. Проверьте landscape, маленький экран, увеличенный шрифт и системные анимации 0×/1×.
6. «Посмотреть дела» из реального BLOCK на холодном и тёплом процессе открывает Привычки сразу. Если CTA приходит во время startup, заставка убирается; BlockSession не удаляется от перехода. Аналогично проверьте переход из уведомления.

## E. Blocking opacity

Тексты показывают фактическое время и число задач; CTA достижима на маленьком экране/при большом шрифте. Home, системные жесты и возврат в ProjectADHD доступны. Окно занимает всю доступную область приложения; системные панели остаются управляемыми.

## F. Live opacity и сохранение

1. Не останавливая мониторинг, откройте Settings → Экран блокировки. Двигайте slider: процент и preview меняются сразу, только scrim затемняет условное содержимое.
2. Быстро проведите 30→90→65 и 65→70→65, сразу уйдите назад, вернитесь. Последнее значение сохранено; поздний ответ DataStore не откатывает slider, надпись «Сохраняется» не зависает.
3. Вернитесь в уже заблокированное приложение. Следующий показ использует новое значение без restart сервиса/мониторинга/приложения. Повторите с Debug → тест блокирующего окна.
4. Для отдельной проверки **уже видимого** test-overlay измените значение через тот же `AppPreferences.setBlockingOpacity` из подключённого отладчика/временного инструментального сценария, пока ProjectADHD Activity скрыта. Сохраняйте через coroutine и возобновите процесс. Уже открытое окно должно изменить scrim без hide/show и перезапуска таймера; состояние BlockSession не меняется. Открытие Settings скрывает overlay намеренно, поэтому само по себе не проверяет этот сценарий. Автотесты в архиве проверяют Flow→существующий controller и перекомпозицию настоящего BlockingContent, но не заменяют проверку реального WindowManager над чужой Activity.
5. После «Сохранено» завершите процесс и запустите приложение снова: значение и preview восстановлены. Перезапустите monitoring вручную; реальный BLOCK использует то же значение.
6. Изменение opacity не меняет pause Praise/fallback, last-praise timestamps, активные BlockSession, baseline и историю. В unit/Android suite проверьте clamp ошибочных значений и восстановление после закрытия DataStore.

## Регрессия Stage 2

Полный сценарий — [STAGE2_MANUAL_TEST.md](STAGE2_MANUAL_TEST.md). Обязательно проверьте:

- При незавершённых задачах и превышении лимита — BLOCK; выход из приложения скрывает окно, возвращение восстанавливает его без новой минуты.
- «Посмотреть дела» не снимает challenge. Только новая допустимая отметка после начала BLOCK закрывает его. Старая completed-задача/её переотметка не даёт unlock; после правильного выполнения начинается новый полный интервал.
- Все задачи выполнены → PRAISE без BlockSession; ноль задач → NONE. Praise исчезает через 4 секунды и соблюдает cooldown.
- Notification fallback без overlay permission; реакции на отзыв Usage Access и запрет уведомлений; STOP из Settings/уведомления/Debug; один сервис и одно окно.
- Обновление поверх Stage 2 сохраняет привычки, отметки, apps, лимиты, историю и активные блокировки; Room остаётся v2. При обновлении с Stage 1 сохраняется прежняя MIGRATION_1_2.

После выполнения внесите реальные PASS/FAIL, логи обеих Gradle-команд, screenshots/video и найденные ограничения устройства. До этого сборка, плавность, отсутствие обрезания масками и фактический перехват касаний считаются **не подтверждёнными на Android**.
