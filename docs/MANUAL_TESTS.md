# Ручная приёмка на устройстве

Эти сценарии подготовлены для проверки пользователем. В среде подготовки они **не выполнялись**.

## Подготовка

Собрать debug-вариант, установить его на Android 7.0+. Дополнительно проверить Android 13+, 14+ и целевой Android 17. Запустить unit/instrumentation-тесты. После первого старта без разрешений приложение должно показывать остановленный мониторинг, пустые данные и доступные экраны привычек/настроек.

## Привычки и сохранение

1. Создать «Прочитать 10 страниц», переименовать, отметить выполненной. Нажать отметку ещё раз для отмены, затем отметить снова.
2. Выключить привычку: она остаётся в списке, не увеличивает число незавершённых. Включить обратно.
3. Пересоздать Activity поворотом экрана, закрыть и открыть приложение, затем остановить процесс и открыть снова. Сохранённые данные должны остаться.
4. Удалить привычку с подтверждением. На отладочном экране количество её отметок должно уменьшиться.
5. Создать незавершённую привычку, дождаться новой местной даты либо использовать отдельное тестовое устройство. Сегодняшняя отметка должна относиться к новой дате. При ручной смене часов учитывать описанное в README защитное поведение cooldown.

## Выбор приложений

1. Найти реально установленное запускаемое приложение по названию и package. ProjectADHD в списке отсутствует.
2. Отметить приложение: лимит 15 минут. Установить 1 минуту, закрыть и открыть приложение: выбор и лимит сохранены.
3. Проверить пустой ввод, 0, 181, буквы: сохранить такой лимит нельзя. Числа 1 и 180 допустимы.
4. Снять отметку: мониторинг этого приложения отключается, лимит сохраняется.
5. Удалить выбранное тестовое приложение с телефона. После обновления списка сохранённая запись помечается недоступной; её можно убрать.

## Разрешения и запуск

1. Отказаться от Usage Access: приложение не падает и не начинает мониторинг.
2. На Android 13+ отказать в POST_NOTIFICATIONS. Мониторинг остаётся остановленным. Включить разрешение через системные настройки.
3. Отключить любой из двух каналов. На главной виден недоступный канал; запуск заблокирован.
4. Выдать Usage Access, включить уведомления и оба канала. Нажать запуск один раз, затем несколько раз быстро: работает один сервис, одно постоянное уведомление.
5. Остановить с главной. Затем запустить и остановить действием в системном уведомлении. Статус меняется на «Остановлен».
6. В процессе мониторинга отозвать Usage Access, потом отдельно уведомления/канал. Сервис должен остановиться на очередной проверке либо вместе с процессом по решению Android. После возврата виден актуальный статус; падения Activity нет.

## Реальное вмешательство

1. Создать две активные незавершённые привычки, выбрать приложение с лимитом 1 минута; cooldown для теста поставить 1 минуту.
2. Нажать «Начать мониторинг», открыть выбранное приложение и использовать непрерывно минимум 65–75 секунд. Допускается большая задержка со стороны Android/OEM.
3. Ожидать уведомление с названием приложения, минутами сессии и числом 2. Нажатие открывает ProjectADHD.
4. В статистике проверить новое событие: длительность не меньше лимита, лимит 1 минута, число привычек 2.
5. Повторно открыть выбранное приложение. До окончания cooldown нового уведомления нет. Смена приложения cooldown не обходит.
6. Дождаться истечения cooldown, оставаясь в выбранном приложении после достижения лимита. Возможен новый сигнал.
7. Очистить историю в отладке: привычки и лимиты остаются, существующий cooldown не сбрасывается.
8. Проверить ситуацию без привычек: уведомление допускается с количеством 0.

## Границы сессии

1. Использовать приложение 40 секунд, перейти в другое, вернуться. Для нового вмешательства снова нужна полная сессия не менее минуты, если cooldown свободен.
2. Перейти между внутренними экранами выбранного приложения. Короткая смена Activity одного пакета не должна обнулять сессию.
3. Погасить экран/заблокировать телефон на 30 секунд. Время блокировки не должно продолжать активную сессию. После разблокировки допускается ожидание нового foreground-события.
4. Проверить PiP и разделённый экран отдельно: Stage 1 учитывает последний RESUMED-пакет, а не доказывает внимание пользователя.
5. Убрать ProjectADHD из последних приложений: на стандартном Android FGS может продолжить работу; проверить поведение конкретной прошивки.
6. Force stop, системная остановка FGS и перезагрузка: скрытого автозапуска нет. После открытия приложения мониторинг запускается вручную.

## Статистика и отладка

1. Статистика показывает выбранные приложения, их лимиты и оценку времени сегодня. Новые события сверху; пустые состояния понятны.
2. При отсутствии Usage Access история доступна, но оценка использования недоступна. После выдачи разрешения нажать обновление.
3. Тестовое уведомление помечено как тест и не увеличивает количество вмешательств, не меняет cooldown.
4. Симуляция даёт Notify для 20/15 минут и двух привычек, не создаёт Android UsageEvents и не пишет историю.
5. Сравнить количество записей на отладочном экране до и после изменения привычек/приложений.
6. Проверить светлую/тёмную тему, крупный шрифт, узкий экран и поворот. Экраны прокручиваются, кнопки доступны.
7. Собрать release: кнопка и маршрут отладки отсутствуют.

## Фиксация результатов

При проблеме сохранить версию Android, модель/прошивку, последовательность действий, состояние разрешений/каналов, экран отладки и Logcat. Не публиковать историю использования или приватные данные в открытых отчётах. Разница с Digital Wellbeing сама по себе не означает ошибку: Stage 1 считает интервалы доступных UsageEvents.
