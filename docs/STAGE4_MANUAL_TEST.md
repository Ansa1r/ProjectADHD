# Stage 4 — проверка на Android

Статус: сценарии подготовлены, **в этой среде не выполнены**. Использовать отдельный тестовый телефон/эмулятор с чистым профилем приложения и копией реальных данных для отдельной migration-проверки.
Нужны Android Studio/JDK/SDK из существующего проекта, Usage Access, Notifications и Overlay permission для полного BLOCK flow. Желательно проверить API 24–25 (fallback), 26+, 33+ (Photo Picker) и актуальную целевую версию.

## Перед началом

1. Распаковать ZIP в новый каталог, открыть корень с settings.gradle.kts. Не накладывать его поверх старого дерева.
2. Выполнить `./gradlew testDebugUnitTest`, `./gradlew assembleDebug`, затем на отдельном эмуляторе `./gradlew connectedDebugAndroidTest`.
3. На Windows использовать `gradlew.bat`. Проверить появившуюся `app/schemas/.../3.json` после успешного KSP build.
4. Установить debug APK, пройти permissions flow, выбрать отвлекающее приложение с лимитом 1 минута и запустить monitoring на Home.
5. Для коротких реальных тестов привычки использовать **00:01**. Debug overlay test не завершает привычки и не начисляет XP.

## A — Profile / avatar

1. На Home вместо ProjectADHD сверху аватар + nickname, справа Settings; «Добрый день» и другое приветствие отсутствуют.
2. Нажать изображение и отдельно имя: оба ведут в Profile. В нижней навигации Profile отсутствует.
3. Без фото виден символ пользователя, не Боб. Statistics X/Y, приложения и вмешательства совпадают с фактической БД/действиями.
4. Открыть Edit Profile → Изменить аватар. Системный Picker показывает только выбор изображения, приложение не запрашивает полный доступ к галерее.
5. Выбрать фото, проверить моментальное изменение Profile/Home. Перезапустить процесс, удалить исходное фото из галереи: сохранённый аватар остаётся.
6. Повторить для повёрнутого EXIF JPEG, PNG и широкого изображения. Убедиться в аккуратном круглом crop, без вытягивания.
7. Отменить Picker — прежний аватар остаётся. Повреждённый/слишком большой файл — понятная ошибка, старое фото остаётся.
8. Изменить nickname, проверить trim, emoji, ограничение 32 code points, отказ blank. Повторный запуск сохраняет имя; изменение аватара не меняет nickname.
9. «Мой прогресс» открывает реальную статистику, Back возвращает в Profile. Внутренняя навигация не повторяет startup.

## B — Mascot

1. Пять bottom icons: Home, Habits, Apps, Stats, Mascot. Включить TalkBack, проверить descriptions и выбранное состояние.
2. Mascot: Боб, level 1/0 XP/0 completed/0 streak на чистой установке. Это начальное состояние, не демонстрационные данные.
3. Изменить имя персонажа, перезапустить — имя сохранилось, nickname пользователя не изменился.
4. Открыть «Кастомизация» — рабочая заглушка без fake items. Открыть «История развития» — пустое состояние до первых наград.
5. После наград сверить общий XP, level и заполнение прогресса между текущим и следующим threshold.

## C — MANUAL accumulation

1. Add Habit открывает отдельный экран. Название Reading, время 00:30, «Без приложения»; сохранить.
2. Проверить невалидные 00:00, 00:60, 24:00, пустое название. Сохранение недоступно.
3. Start → IN_PROGRESS. Свернуть, заблокировать экран на несколько минут, вернуться — daily progress включает это время.
4. Pause, запомнить progress, подождать — он не меняется. Resume → накопление продолжается.
5. Выполнить несколько отрезков; сумма сохраняется, не требуется непрерывная сессия.
6. Запустить другую MANUAL habit: первая PAUSED, её progress сохранён.
7. Убить только процесс после checkpoint и вернуться в том же boot — elapsed время восстановлено. Полный reboot — только сохранённый checkpoint и PAUSED, без времени выключенного телефона.

## D — MANUAL confirmation / NO

1. Создать отдельную тестовую MANUAL привычку с 00:01. Start, дождаться цели.
2. Timer остановлен на target, COMPLETED ещё нет, XP не изменился. Idle Bob спрашивает о результате, отображает привычку/required time.
3. Проверить на Habits и при достижении на Home/Mascot: там появляется диалог. При warm start сначала полностью заканчивается прежняя заставка.
4. NO → прогресс 1 / 11 минут, base target по-прежнему 1, extra=10, timer продолжает идти.
5. Достичь 11 → NO → 11 / 21, extra=20. Прогресс не сбрасывается.
6. Достичь 21 → YES: COMPLETED, одна Habit XP, счётчик +1. Быстро повторить нажатия/перезапустить: дублей нет.
7. «Позже»/закрытие диалога оставляет AWAITING_CONFIRMATION, не выполняет задачу и не снимает блокировку.

## E — APP_BASED accumulation

1. Создать полезную привычку с установленным приложением (например Duolingo), 00:01. Linked app не должно быть ограничено.
2. «Открыть приложение» запускает его и monitoring при выданных разрешениях. Foreground 20 секунд → прогресс около 20 секунд (polling delay допустим).
3. Home/другое приложение/lock на 20 секунд → полезное время не растёт.
4. Вернуться в linked app ещё на 20 + 20 секунд в разных сессиях → 60 секунд, COMPLETED автоматически, без checkbox/YES.
5. Habit XP и completion записаны один раз; дополнительные минуты не начисляют новые rewards.
6. Перезапустить процесс между сессиями: доступная история UsageEvents восстанавливает время без удвоения.
7. Полный reboot в середине дня: ранее надёжно записанная база сохраняется, время выключения не учитывается, новая загрузка добавляет новые foreground интервалы.
8. Остановить monitoring, уйти из UI: фоновые usage-запросы прекращаются. Вернуться в UI: прогресс уточняется по доступной истории. Для мгновенного auto completion в фоне включить monitoring.
9. Удалённое linked app или отозванный Usage Access дают понятное состояние, не создают fake progress.

## F — оба конфликта

1. Ограничить Duolingo на Apps и сохранить. В Create Habit выбрать приложение: Duolingo disabled + «Ограничено» и пояснение.
2. Снять ограничение, сохранить. Теперь приложение выбирается в привычку.
3. Создать активную app habit. В Apps её приложение disabled + «Используется в привычке».
4. Архивировать habit — приложение можно ограничить. Попытка снова активировать habit при ограничении отклоняется без потери данных.
5. Instrumentation fixture legacy conflict: данные обеих записей сохранены, BLOCK этого package не активируется. На Apps можно снять старое ограничение, на Habits/Debug видна диагностика.
6. При быстрых параллельных сохранениях конфликт не проходит repository transaction.

## G — BLOCK + MANUAL

1. Нужна невыполненная MANUAL привычка на 00:01. Превысить минутный distracting limit.
2. Видны underlying app, purple scrim 0.85, blocking Bob, непрозрачные текст/кнопка. Тапы не проходят в blocked app. Системная Home/навигация доступны.
3. «Посмотреть дела» ведёт в Habits, BlockSession остаётся active. Start manual, погасить экран.
4. После target открыть blocked app: вместо blocking Bob — idle Bob и confirmation.
5. NO оставляет block active и добавляет 10 минут, не сбрасывает progress. Возврат в app до новой цели снова показывает blocking Bob.
6. После новой цели YES освобождает BlockSession и выдаёт XP. Повторный тик не создаёт дубль release/history.
7. Возврат в distracting app получает новый полный интервал от releasedAt, не мгновенный старый BLOCK.

## H — BLOCK + APP_BASED

1. Создать 00:01 app habit, вызвать distracting BLOCK, открыть Habits, запустить linked app.
2. Реальный foreground time достигает 60 сек → auto completion, один Habit XP, eligible BlockSession RELEASE.
3. Вернуться в distracting app: overlay закрыт, новый полный session interval.
4. Переключения/lock не засчитываются; один только CTA «Посмотреть дела» не освобождает блок.

## I — раннее выполнение / PRAISE

1. Выполнить все активные привычки заранее, до отвлекающих приложений.
2. Превысить distraction limit — happy PRAISE, никакого BLOCK.
3. Проверить независимый PRAISE cooldown, отсутствие повторных наград за сам PRAISE.
4. При нуле активных задач — NONE, нет BLOCK/PRAISE и искусственного streak XP.
5. Без overlay permission работает прежний fallback notification; без notification permission monitoring показывает существующее объяснение.

## J — XP / streak / календарь

1. На чистом профиле создать две MANUAL привычки 00:01. Выполнить первую → +5 XP, streak ещё 0.
2. Выполнить вторую → ещё +5 Habit XP, +10 Streak XP, total20, level2, streak1.
3. Несколько раз открыть экраны и перезапустить процесс — XP20/streak1 без дублей.
4. Следующий локальный день: daily0, extras0, base target сохранён, XP/history прежние. Всё выполнить → новая однократная дневная награда.
5. Пропустить активную задачу до конца дня → на следующей дате streak0. Пустой день не выдаёт XP и не увеличивает серию.
6. Добавить новую задачу после дневной награды, оставить незавершённой: XP не отнимается, но следующая дата сбрасывает серию.
7. Проверить в repository tests: XP145 (level10), Habit+5 → level11; следующая Streak награда +15, а не +10.
8. Проверить границы 14/15, 29/30, 149/150, 169/170; thresholds150→170, не165. Unit tests покрывают также высокие уровни и ceil.
9. Удаление выполненной привычки сохраняет уже заработанный XP/award history. Migration завершений не создаёт ретроактивный XP.
10. Полночь во время manual: вчерашняя сессия закрыта, сегодня READY/0; вчерашнее AWAITING не позволяет подтвердить сегодня. Повторить на датах DST/изменения часового пояса.

## K — регрессии и визуальная проверка

- Apps checkbox draft → Continue → individual limits → Save; существующие лимиты/иконки, apply all и Home без обязательного Save сохранены.
- Settings gear, permissions, cooldown/PRAISE settings, Debug, statistics и history остаются доступны.
- Opacity slider и preview нигде не появляются; значение85 фиксировано. Старый preference не влияет.
- Home/Habits/Apps/Stats/Profile/Mascot: fill85, outline/text/icons100. Проверить refresh/search/nickname/setup controls.
- BLOCK не использует background07 и рамку телефона; full-screen touch-blocking. Praise сохраняет безопасный touch-through.
- Проверить небольшой экран, landscape, font scale1.5/2.0, клавиатуру и скролл длинной привычки/списка.
- Cold/warm start: полный Боб → flip → название → fade; внутренняя навигация не повторяет заставку. CTA OPEN_HABITS после заставки остаётся на Habits.
- Launcher adaptive/round/legacy и monochrome соответствуют прежнему happy mascot, без старого template icon.
- STOP очищает активные blocks и скрывает overlay; ручной таймер при этом независим. Debug tests не выдают production XP.

## L — migration / сохранение данных

1. На копии v0.3.1 создать активные/архивные habits, completions, app limits, event history, BlockSession, nickname.
2. Установить v0.4 поверх без удаления данных. Все прежние записи остаются; old habits становятся MANUAL/30 минут.
3. Старое завершение отображается как выполненное без выдуманного времени. totalXP0, completion counter соответствует сохранённым записям.
4. Проверить прямую v2→v3 и цепочку v1→v2→v3 через instrumentation tests.
5. Симулировать DB failure trigger из Stage4RepositoryTest: completion, XP и block release откатываются совместно; повтор после исправления проходит один раз.

Результаты заполнить после фактического прогона: устройство/API, commit/source ZIP, команды и их exit codes, сценарий, фактический результат, screenshot/log при расхождении.
