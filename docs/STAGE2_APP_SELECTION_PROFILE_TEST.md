# Stage 2 — App Selection & Profile Fix: ручная приёмка

Версия 0.3.1-pre-alpha, versionCode 5. Этот документ — **план**, а не запись пройденных проверок. Подготовка выполнена без Android SDK/эмулятора. Запишите Android API/OEM, режим системной навигации, ориентацию, шрифт, фактические результаты и screenshots/video.

## Подготовка и сборка

Откройте корень распакованного проекта в Android Studio с рабочими JDK и Android SDK текущего Stage 2. Выполните:

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebug
./gradlew connectedDebugAndroidTest
```

Windows: `gradlew.bat`. Объявлено 92 unit-теста и 24 Android-теста. Здесь обе первые команды завершились exit 1 при скачивании Gradle 9.6.0: `Network is unreachable`; тестовые задачи и компиляция не выполнялись. Android-тесты запускайте на отдельном эмуляторе с тестовыми данными: UI-сценарии временно заменяют tracked selection, что снимает активные блокировки.

После успешной сборки APK находится в `app/build/outputs/apk/debug/app-debug.apk`. Отдельно проверьте обновление поверх предыдущего Stage 2 тем же signing key без удаления данных. Для clean-install сценария используйте другую установку/эмулятор. Package — com.ansa1r.projectadhd. Выдача разрешений: Главная → шестерёнка → Разрешения.

## A. First selection

1. Чистая установка или ноль включённых tracked apps. После загрузки данных Home показывает «Выбрать приложения».
2. Откройте карточку. В каждой строке только иконка PackageManager, display name и checkbox. Нет package name, лимита и технического текста. Поиск работает по названию; сам ProjectADHD и исключённые системные приложения не предлагаются.
3. Выберите Chrome и YouTube (или два доступных обычных приложения). До Save production tracked list остаётся пустым; профиль/monitoring не считают draft применённым.
4. Появляется закреплённая снизу кнопка «Продолжить». Откройте отдельный экран «Настройка лимита».
5. На нём только выбранные приложения; у новых — 15 минут. Установите Chrome=10, YouTube=30.
6. Введите общий лимит 20, нажмите «Применить ко всем»: оба значения становятся 20. Измените Chrome обратно на 10: YouTube остаётся 20.
7. Проверьте пустое значение, 0, 181: Save недоступна, ошибка объясняется. Значения 1 и 180 допустимы.
8. Нажмите Save при Chrome=10, YouTube=20. Вернитесь на Home автоматически. Первичная карточка исчезла, Apps tab остаётся.
9. Через Apps проверьте отмеченные приложения. В строках нет лимитов; «Настроить лимиты» открывает сохранённые 10/20 без обязательного изменения галочек.
10. Мониторинг использует новый выбор и лимиты без restart приложения/сервиса. Проверяйте новые лимиты на приложениях без уже активного BlockSession; лимит не является способом обойти действующий challenge.

## B. Navigation bug

- Откройте Apps при пустом tracked list, ничего не выбирайте, нажмите Home icon: Home открывается.
- Повторите при существующем selection, изменённом selection и снятых всех галочках.
- Откройте Session Limit Setup, оставьте невалидный лимит и нажмите Home: переход не блокируется.
- Повторите переход Apps/limits → Tasks/Stats/Profile. Внизу всегда ровно пять иконок без подписей, с contentDescription и selected indicator.
- Системный Back из limits возвращает selection с тем же draft. Back из selection закрывает flow. Bottom Navigation на другую вкладку отбрасывает draft.
- В Settings и Debug Back работает как прежде; Settings остаётся через шестерёнку Home.

## C. Unsaved draft и повторное редактирование

1. Запомните сохранённый набор и лимиты. Добавьте приложение и снимите другое, затем уйдите через Home без Save.
2. Room/monitoring/profile должны сохранить исходный набор. При новом открытии Apps исходные checkbox восстановлены.
3. Повторите уход без Save со страницы лимитов после индивидуального изменения и Apply all: production лимиты не меняются.
4. Выберите дополнительное приложение, Continue: существующие лимиты сохранены, новое получает 15. Save заменяет весь набор одной операцией и возвращает Home.
5. Нажмите Save и сразу перейдите на другую вкладку. Явно начатая запись должна завершиться; поздний результат не возвращает принудительно на Home. При новом входе данные совпадают с persistence.
6. Поверните экран внутри flow: ViewModel сохраняет текущий draft. При уничтожении процесса несохранённый draft может сброситься; сохранённые данные должны остаться. Если восстановился пустой limits screen, доступен возврат к выбору и Home.
7. Ошибку записи/атомарный rollback проверяет AppSelectionRepositoryTest с abort-trigger: старый набор, BlockSession и history остаются целиком. Пользовательский экран при ошибке показывает сообщение и позволяет повторить Save.
8. Удалите ранее выбранное приложение из Android: его сохранённая строка с fallback-иконкой остаётся доступной для снятия выбора. Save не оставляет ghost tracked rows.

## D. Remove all и active BlockSession

1. Создайте две незавершённые привычки и реальный BLOCK тестового приложения.
2. Через системный Home откройте ProjectADHD → Apps. Снимите blocked app и сохраните оставшийся набор. После Save удалённый пакет не tracked, его challenge не active, причина снятия TRACKING_DISABLED; возврат в него не блокируется.
3. Снимите все оставшиеся галочки. Кнопка должна называться «Сохранить», без перехода на пустую страницу лимитов.
4. Save → Home. Карточка «Выбрать приложения» появилась; профиль показывает ноль tracked apps. Monitoring не падает, старые окна не появляются, системная навигация и пять вкладок работают.
5. Не нажимайте аварийный STOP до проверки этого сценария: иначе он сам снимет challenges и скроет ошибку удаления selection.
6. Добавьте приложение заново: оно получает новый обычный цикл мониторинга, старый active block не восстанавливается.

## E. Startup

- Cold start через launcher: стилизованный системный фон → полный happy PNG на градиенте → flip → ProjectADHD → fade в приложение.
- Нет круглого контейнера, circular crop, обрезанного шарфа/капель или отдельного маскота под маской системного splash. Проверьте маленький экран, landscape и увеличенный шрифт.
- Собственная последовательность номинально 1840 мс (420+300+300+420+400). Проверьте плавность и диапазон около 1.7–2.2 с при обычном масштабе системных анимаций. Загрузка процесса ОС измеряется отдельно.
- Включите monitoring, нажмите системный Home, убедитесь, что FGS продолжает работать. Откройте ProjectADHD через launcher: анимация повторяется.
- Повторите возврат из другого приложения, через recents и после блокировки/разблокировки устройства. Остановка FGS для этого не требуется.
- Переключайте внутренние tabs, Settings, Profile edit и limits: startup не появляется.
- Поверните устройство/пересоздайте Activity: startup не должен повторяться только из-за конфигурации. Если поворот был во время заставки, допустимо завершение текущего показа без нового полного цикла.
- Полупрозрачный системный диалог/шторка или смена фокуса в split-screen при всё ещё видимой Activity сами по себе не считаются уходом UI в фон.
- «Посмотреть дела» при скрытой Activity тоже запускает короткую анимацию; после неё открываются привычки, не Home. Переход не удаляет BlockSession; новая допустимая отметка по-прежнему нужна для unlock.
- Если выйти во время анимации, следующий реальный вход начинает её заново. UI-черновик при простом background/foreground сохраняется, если процесс жив.

## F. Profile

1. Откройте Профиль: фон 07, маскот, purple-карточки, локализованный «Пользователь» до задания имени.
2. Сверьте X/Y с реальными активными привычками сегодня, число приложений — с сохранёнными enabled TrackedApp. Изменение draft без Save не меняет показатели.
3. «Вмешательств сегодня» считает события всей локальной даты, а не только 200 последних. BLOCK_TRIGGERED, PRAISE_SHOWN, LEGACY_NOTIFICATION и fallback PRAISE учитываются; BLOCK_RELEASED и fallback того же BLOCK не прибавляют ещё одно вмешательство. Сверьте журнал/SQL; после очистки истории счётчик уменьшается.
4. «Мой прогресс» и «Достижения» открывают отдельные заглушки. Нет fake achievements, streak или придуманного email.
5. «Редактировать профиль» → введите «Максим» → Save. Название обновляется в профиле без restart. Начальные/конечные пробелы убраны; пустое имя, перенос внутри и больше 32 Unicode code points не принимаются.
6. Повторите с Unicode/emoji. Закройте/откройте UI, поверните экран, остановите процесс и запустите снова: сохранённое имя восстановлено. DataStore reopen отдельно проверяется ProfilePersistenceTest.
7. Измените имя без Save и уйдите Back/Home: сохранённое имя не меняется. Начатый Save завершается и при быстром уходе; поздний callback не перехватывает другую вкладку.
8. Выполните привычку/измените сохранённый tracked list и вернитесь в Profile: реальные показатели обновлены. Проверьте смену локального дня; DST и границы суток покрыты unit-тестами.

Выполните STAGE2_MANUAL_TEST.md и актуальные части STAGE2_UI_REVISION_TEST.md: incomplete+limit → BLOCK, all complete → PRAISE, no tasks → NONE; старые отметки не снимают challenge; новая baseline-задача даёт новый интервал; CTA не снимает challenge; notification fallback, permissions, STOP, Debug, stats и сохранение данных после обновления.

Проверьте opacity 30/65/90 и live slider без restart; маскот/текст/кнопка непрозрачны, касания блокируются, системная навигация доступна.
